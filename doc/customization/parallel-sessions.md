# 並行セッション・複数人でのDD運用（識別子付きDD）

複数のセッション（または複数人）が同じリポジトリで同時に作業すると、DD番号の衝突と互いの作業の巻き込みが起きる。**`DD` + 識別子1〜2文字**で系列を分けると、番号衝突なしに並行運用できる。

> 出典: 利用先案件での実運用（アプリ本体 `DD-` と kintone版 `DDK-` を別セッションで並行開発）を上流反映したもの。

## 系列の分け方

| 使い方 | 例 |
|---|---|
| 複数人 | `DDI-001`（石森）/ `DDSA-001`（斉藤） — **人ごと**に識別子 |
| 並行セッション | `DD-001`（アプリ本体）/ `DDK-001`（kintone版） — **作業系列ごと**に識別子 |

- 識別子は**大文字1〜2文字**。スクリプトの判定 `^DD[A-Z]*-[0-9]` に合わせる（小文字・3文字以上は索引から漏れる）
- 番号は**系列内で連番**を取る（`DD-012` と `DDK-003` は併存してよい）
- 全系列が同じ DD-INDEX.md に載る（`dd-index-gen.sh` が識別子付きも収集する）— 進捗の共有ビューはここに集約

## プロジェクト側 AGENTS.md への書き方（例）

分担表はプロジェクト固有情報なので、各プロジェクトの AGENTS.md に書く:

```markdown
### 並行セッションの分担（識別子付きDD）

| 系列 | 担当範囲 | 触るディレクトリ |
|---|---|---|
| `DD-{番号}` | アプリ本体 | `src/` `doc/` |
| `DDK-{番号}` | kintone版 | `kintone/` |

- 自分の系列外のディレクトリを触らない。共有物（`doc/`・AGENTS.md 等）を変更する
  場合は他系列と衝突しうるのでコミット前に `git status` を確認する
- `git add -A` を使わない。対象ファイルを明示して stage する
  （他セッションの作業や認証情報を巻き込むため）
```

## ルール（要点）

1. **系列 ↔ ディレクトリの対応を固定する** — 自分の系列外は触らない。これで編集衝突がほぼ消える
2. **共有物（doc/・AGENTS.md・DD-INDEX.md）はコミット前に `git status`** — 他セッションの変更が混ざっていないか確認してから stage する
3. **`git add -A` 禁止** — 対象ファイルを明示して stage する。他セッションの作業ファイルや gitignore 漏れの認証情報を巻き込んだ実事故がある
4. **DD-INDEX.md は直接編集せず `bash scripts/dd-index-gen.sh` で再生成** — どの系列から実行しても全系列が1つの索引に載る

## スクリプト・スキルの対応状況

識別子付きDDは配布物が標準対応している（2026-08 の配布版以降。それ以前の版は `dd-index-gen.sh` が識別子付きを索引から落とす）:

- `dd-index-gen.sh` — 識別子付きDDを索引に収集（glob `DD*-*.md` + `^DD[A-Z]*-[0-9]` 判定）
- `dd-health.sh --dd DDK-001` — 識別子を明示すればその系列に限定して検索。番号だけ（`--dd 42`）なら素の `DD-` を優先し、無ければ識別子付きへ広げる（`DD-001` と `DDK-001` 併存時の誤ヒット防止）
- `/dd` スキル — 番号解釈は柔軟（`DDK-001` をそのまま指定可）。新規作成時の連番は系列内の最大番号から取る
