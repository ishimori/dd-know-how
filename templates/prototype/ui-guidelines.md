# 画面の既定値（業務アプリ）

> 業務アプリを試作するときの画面の既定値。画面やモックを作る前に読む。
> プロジェクトの事情で変えるときは、この文書を書き換え、理由（決めたDDの番号）を1行添える。

## 考え方

業務で毎日使う画面として作る。見栄えより、1画面で判断できる情報量と、操作の速さを優先する。

## 画面の骨格

| 領域 | 既定 |
|------|------|
| ヘッダ | 低く抑える。その下のデータの表示・入力領域を主役にする |
| グローバルメニュー | 画面上部に置く |
| サイドメニュー | 上部のメニューに収まらないときだけ、左側に追加する |
| パンくず | 現在位置と、上位の画面へ戻る道を示す（画面間を移るときに迷わせない） |

## 一覧と詳細

- 一覧で項目を選んだら、**詳細画面へ遷移する**。一覧の右側に小さなパネルを出して、詳細を押し込めない
- 画面の大半を使う大きなモーダルで詳細を開いてもよい。ただし、次の2つを満たすこと
- **詳細から前後へ移れる**: 詳細画面に「前へ／次へ」を置き、一覧へ戻らずに隣の項目へ移れるようにする。順序は、元の一覧の検索条件・絞り込み・並び順に従う（ID の連番にしない）
- **一覧へ戻ると元の位置に戻る**: 検索条件・並び順・ページ・スクロール位置・選んでいた行を復元する

## 情報密度

- 余白やカードで高さを使わない。件数・合計などの集計は、一覧の上に1行で置く
- 文字を小さくしたり、コントラストを下げたりして密度を稼がない
